# TARDIS 驾驶模拟器 — 烧烤会话记录

**时间**: 2026-07-31  
**背景**: 用户设计一个文字冒险游戏（TARDIS 驾驶模拟器）来指导 AVM 系统完善，本会话通过 grilling 分析游戏设计需要的 AVM 系统功能。

---

## 游戏架构（已确认）

### 角色层级
1. **玩家对话** — 玩家的交互入口
2. **TARDIS NPC 对话** — 人形界面，与玩家同行，知识受限，可向处理器请求信息和订阅告警
3. **TARDIS 处理器对话** — 后台总览全局，可调 Python 监听特定数据，自主决定发什么信息给 NPC
4. **NPC 对话**（各角色） — 有独立数据结构（目标等），存储于 $MEM
5. **环境管理器对话** — 管理场景、广播环境事件给观察者
6. **NPC 管理器对话** — 管理 NPC 注册、生成、生命周期
7. **房间生成器对话** — 按距离解锁机制生成 TARDIS 内部房间图
8. **故事背景编写对话组** — 世界事件生成

### 核心循环
玩家输入 → 相关 NPC/环境处理 → 留下数据 → TARDIS 处理器汇总 → 下一循环。这些对话自身就在 Core 调度队列中，不独立于调度器。

### 事件分类
- **实时事件**：对话间交互产生（Dalek 呼叫舰队 → NPC 管理器生成 → 环境管理器记录并广播）
- **世界事件**：TARDIS 驾驶阶段由故事背景编写对话组生成

### TARDIS 内部探索（当前优先测试）
- 非欧几里得房间图（向前走和向后走可能到达不同房间）
- 不保存路径，保存**玩家到特定锚点房间的距离**
- 锚点房间：TARDIS 控制室（必然存在）、和谐之眼、ARS 系统室
- 距离足够近时，房间生成器生成连接到该锚点的路径
- 类似 roguelike，移动时动态生成房间

### 权限设计（故意制造的问题）
- TARDIS 处理器可以访问 NPC 数据结构，可能滥用职权
- NPC 通过 Capabilities 模型只知道传入的路径，不能越界
- 这恰好用于测试内核态/用户态权限分离和安全模型

## 已识别的 AVM 缺失/待增强功能

| # | 游戏需求 | 对应的 AVM 功能 | 当前状态 |
|---|---------|---------------|---------|
| 1 | TARDIS 处理器调 Python 监听特定数据 | **Python 对话作为一等执行单元** (`type="python"`) | 未实现 |
| 2 | 多个对话在一回合内协同（游戏循环、TARDIS NPC、处理器、各 NPC） | **并发对话执行** / 至少多对话协作模式 | 未实现（当前单活跃对话轮转） |
| 3 | 游戏循环对话是调度者但不能碰 Core 内部队列 | **内核态 vs 用户态分离** | 设计中，未实现 |
| 4 | NPC 只能访问被授予的 $MEM 路径 | **Capabilities 安全模型**（工作区映射、禁止 root 遍历） | 设计中，未实现 |
| 5 | TARDIS 处理器主动推送告警给 TARDIS NPC | **对话间异步消息/回调**（非 `call_service` 的请求-响应模式） | 未实现 |
| 6 | 房间生成器每次移动时被调用，输入状态后输出新房间 | **动态对话创建 + 参数传递**（`create_cmd`/`create_sub` 已支持基础形式） | 已实现基础形式，需验证参数传递是否够用 |
| 7 | 环境管理器广播事件给"所有正在看着的 NPC 和玩家" | **事件广播 / 发布-订阅机制** | 未实现 |
| 8 | NPC 管理器注册/生成/销毁 NPC 对话 | **对话生命周期管理 API**（从用户态调用，不操作 Core 内部） | 部分实现（`register_service`、`create_cmd` 存在，但无"销毁"和"挂起"的用户态 API） |
| 9 | 故事背景编写对话组在 TARDIS 驾驶阶段运行 | **对话组 / 批处理 / 流水线执行** | 未实现 |
| 10 | 玩家在 TARDIS 内部移动，状态需要持久 | **游戏状态持久化**（$MEM 的 save/load 已支持，需验证在复杂图中是否够用） | 已部分实现 |
| 11 | 距离计算：每次移动后重新计算到各锚点距离 | **Python 对话的计算能力**（同 #1） | 未实现 |

## 待继续的烧烤问题

**问题 12（中断）**：房间生成器对话的职责范围——输入输出、是否将新房间注册进全局房间图。

后续应继续的路线：
- 房间图的结构和存储（$MEM 中如何组织房间数据）
- TARDIS 驾驶阶段的目的地生成和故事背景的衔接
- NPC 生命周期（生成、挂起、销毁的时机）
- TARDIS 处理器的权限滥用如何在设计中隔离
- 世界事件与实时事件的优先级和冲突处理
