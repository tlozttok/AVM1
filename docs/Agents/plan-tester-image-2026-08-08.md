# 计划：全局测试者镜像（tester.json + 参考手册入 Mem）

**时间**: 2026-08-08
**状态**: 已实施（2026-08-08）；同日按用户反馈修订
**背景**: AVM 功能变复杂（调度、ICC、多播、PLM、信息设备、沙箱、思维链回传），需要一个可观测并操作系统全局状态的对话做模糊测试。
**起因**: 用户要求：写一份包含 overview 的完整测试者文档，放入测试镜像的 Mem；在测试者对话的提示词中告知手册位置；具体任务由用户后续在提示词中给出。随后用户明确：该对话用于模糊测试，不加行为限制，任务、工具调用与用户交互方式由用户自己给出。
**行动**（最终形态）:
1. 新增 `images/tester.json` 测试镜像：init 对话 tester（cid 0）。system 提示词只给身份与参考指引——指向 `$MEM.tester_manual`、列出可用工具；不预设任务、不规定交互协议、不写行为限制。init user="开始"（占位，任务由用户编辑此节点或在运行时输入）。
2. Mem 新增 `$MEM.tester_manual`（dict 节点，meta 描述 + 5 个 str 章节：overview / observe / instruction_ref / memory_model / scheduling），内容为纯机械参考：系统结构、信息设备路径、指令签名、内存语义、调度规则。不含设计哲学、不含行为规定、不含测试方法指令。
3. Mem 保留 `$MEM.test` 工作区（plans / results / notes）与预置 Python 程序（`$MEM.programs.probe_simple` / `probe_python`，对应 `$MEM.para.simple` / `python`）作为可用资源，不预设用途。
4. 挂载 inputs / outputs 设备（复用 `images/devices/io.py`）；`persist_to=out/tester_mem.json`。

**修订记录（2026-08-08，用户反馈）**:
- 用户反馈：该对话用于模糊测试，不要加限制；不要告诉它要做什么；它不是一个 AVM 设计哲学下的程序；AVM 设计哲学本身也不应向 AI 对话透露。
- 删除：system 提示词中的主循环、证据纪律、拆分原则、错误处理、预算要求、退出协议等行为规定；手册中的 test_method、reporting 章节；overview 中的“测试者定位”“不做的事”等哲学表述。

**设计原则记录（用户提出并明确要求记下）**:
- AVM 程序设计哲学不应向 AI 对话透露。
- 原则表述：“用具体到任务的提示告诉 AI 要怎么做，而不是直接把哲学给他。”

**影响**:
- 手册只承载可验证的机械事实；对话行为完全由具体任务提示驱动，符合“提示词是控制律”而“哲学不下发”的边界。
- 手册与运行时行为对齐（指令签名、信息设备路径、预算语义）；后续 AVM 行为变化时需同步更新。
- 测试者拥有 `$MEM` 全权访问是测试镜像的既定性质（内核态/用户态隔离未实现）；宿主侧沙箱是唯一外部边界。

**发现的设计缺失（建议 issue）**:
- 指令集没有设置/修改 ctrl 元数据的工具：对话无法在运行时创建 Python 程序节点，只能使用镜像预置的程序。
- 无内核级关闭指令：对话无法终止失控的其他对话，只能依赖指令预算中断与休眠。
