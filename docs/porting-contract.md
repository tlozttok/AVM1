# AVM 移植契约（Porting Contract）

本文是"把外部编排方案写成 AVM 软件"的交付约定。读者有两类：**执行者**（拿到契约去移植的人或 Agent）与**验收者**（安装、使用并判断是否保留它的宿主/操作员）。

契约不规定外部方案长什么样，只规定交付物的形状与验收方式。术语以 [CONTEXT.md](../CONTEXT.md) 为准；运行机制见 [docs/runtime.md](runtime.md)；程序写法见 [docs/programming-guide.md](programming-guide.md)；包与持久运行的机制见 [docs/runtime.md 的「持久运行」](runtime.md#持久运行重启恢复--回合日志--程序包)；一个完整示例见 [images/packages](../images/packages/README.md)。

## 交付物

一次移植交付六样东西。缺任何一样，验收者都无法在不读代码的前提下判断它能不能用。

| # | 交付物 | 内容 | 验收方式 |
|---|---|---|---|
| 1 | 程序包 `*.pkg.json` | `meta` + `mem` + `devices` 三段，格式以 [avm/packages.py](../avm/packages.py) 的模块 docstring 为准 | 能装进演示镜像并被 `create_cmd` 使用 |
| 2 | 设备文件（按需） | `MemoryDevice` 子类；不发事件；错误信息不回显写入原文 | 装包/卸包后挂载点随之回收 |
| 3 | `README.md` | 做什么、怎么用、能力声明、已知退化 | 验收者只读它就能上手 |
| 4 | 保真度账本 | 一致 / 退化 / 未实现 三栏 | 每条退化有原因，能对照原方案核查 |
| 5 | 行为场景 | 输入序列 → 可观察输出，脚本化 | 自测里可重复跑 |
| 6 | 自测 | 用 MockLMU，`python -m pytest` 可跑 | 全绿，且不调真实 API |

程序包的结构：

```json
{"meta": {"format": "avm.package", "version": 1,
          "name": "supervisor", "package_version": "0_1_0",
          "description": "监督者-工人协作"},
 "mem": { "programs": {"kind": "dict", "value": {}}, "params": {"kind": "dict", "value": {}} },
 "devices": [{"path": "io", "file": "io.py", "class": "EchoDevice", "args": {}}]}
```

安装后：包内存在 `$MEM.packages.<name>.<package_version>`，安装记录在 `$MEM.package_records.<name>.<package_version>`，当前版本指针是 `$MEM.packages.<name>.current`。设备条目的 `path` 相对包子树，`file` 相对包文件所在目录。

## 硬约束

违反任何一条，交付即不合格。

1. **不改 `avm/`**：不加指令、不改事件类型、不改调度状态机、不改 `Core` 的行为。移植发生在镜像与程序层。
2. **不用未实现的能力**：`$time` / `$sleep` / `$random` 设备、整棵子树删除、运行期创建或改写链接、运行期注册 PLM、事件持久化与重放、定时器、中断优先级与屏蔽位、文件密码。需要这些的机制，在账本里记"未实现"，不要绕过。
3. **能力最小化**：程序节点用 `value.caps` 声明子对话的模式、根与工具集（见 [docs/capabilities.md](capabilities.md)），只申请做到这件事需要的部分。
4. **不调真实 API**：自测全部使用脚本化执行器（`tests/test_avm.py` 的 `MockLMU` 是参照）。真实行为由验收者负责。
5. **包只含 `mem` 与 `devices`**：自定义 PLM 是核级注册表，不随包分发；需要 Python 逻辑时写成 `plm.python` / `plm.command` 程序节点。
6. **版本号是内存键**：`package_version` 不能含点号（点号是路径分隔符），用 `1_0_0` 这样的形式。
7. **跨轮状态落在 `$MEM`**：Python 程序的状态放在 `$MEM`，不要放在 PLM 命名空间变量里；恢复时命名空间会重建（见 [docs/programming-guide.md](programming-guide.md) 的「持久运行与跨轮状态」）。

## 怎么移植

1. **写机制清单，不写品牌。** 例如"监督者派活、工人回报、状态落黑板、完成唤醒下游"。逐条标：必须保真的、可以退化的、当前原语做不到的。
2. **逐条映射到 AVM 原语**，先只写落点，不写实现：

| 外部编排里的东西 | AVM 里的落点 |
|---|---|
| 角色 / 智能体 | 对话：LLM 用 `settingup` 程序，确定性逻辑用 `python` 程序 |
| 共享状态 / 黑板 | `$MEM` 子树；描述写给模型看，控制数据写给运行时看 |
| 消息 / 事件 | `send_instruction` 投递；`listen_event` + 处理器返回 `notify` |
| 工具 | 10 条指令 + PLM 程序 + 设备 |
| 工作流 / 图 | 对话链（`create_sub` 同步链）或事件驱动（监听 + 唤醒） |
| 派生执行者 | `create_sub` 紧耦合、用完即删；`create_cmd` 独立个体、休眠等指令 |
| 人机审批 | `$inputs` / `$outputs` 设备 + 一个等待节点 |
| 运行日志 | 监测帧与 `$MEM.monitor` |

3. **先跑最小链路**：一个对话 + 一次投递 + 一次等待 + 一次结果落盘。链路通了再扩角色与分支。
4. **写账本与场景**。账本按机制逐条写，不按目录结构写；场景给输入与可观察输出，不写内部状态。
5. **自测绿了再交付**，并在 `README.md` 里写清"装好之后应当看到什么"。

## 能力声明

`README.md` 里必须有一节，列出这个包会碰什么：

```text
模式：用户态 / 内核态
根：pkg（包自己的子树）、mem（如需要读全局状态）
工具：memory_read, memory_write, create_cmd, send_instruction, listen_event
创建对话：是（LLM / Python）
设备：io（读写包内路径）
外部副作用：无
```

验收者据此判断是否安装。没有这一节，安装时无法评估。

## 验收

**交付前（执行者）**：

```bash
python -m pytest <包目录或 tests/ 下的自测> -q    # 全绿
```

自测至少覆盖：包能装、包能卸、场景按顺序跑通、卸载后包内路径不可用。

**交付后（验收者）**：

1. 在暂存路径装包（先装再决定，不直接进主系统）；
2. 按 `README.md` 跑一遍场景，对照"应当看到什么"；
3. 对照能力声明，确认没有超出预期的访问；
4. 通过则提升为正式包，不通过则卸载并记录原因。

判据三条：不改包就能用；实际能力与声明一致；账本里的退化项可以接受。

## 常见错误

- **表面移植**：把原方案的流程图翻译成对话链，顺手把关键机制改成好实现的形态，账本里却写"一致"。例如"父创建子后继续执行、不等待"被写成"父等子返回"。
- **能力过宽**：为了好写，给程序申请 `$MEM` 根和全部工具。安装者无法判断边界。
- **用未实现特性**：写了 `$sleep` 或在提示词里要求链接换向，自测因为没执行到而变绿。
- **拿亚对话做任务执行**：[CONTEXT.md](../CONTEXT.md) 对亚对话的定性是紧耦合、不可信、用于省 token；父是确定性 Python 程序、system 提示词由程序生成时另说，但要在账本里写明理由。
- **版本号带点**：`1.0.0` 装不进去，因为点号是路径分隔符。
- **Python 状态放命名空间**：自测能过，恢复后状态丢失。
- **设备发事件或回显内容**：装载类设备一旦发事件，写入内容会出现在事件载荷里。

## 交付与版本

- 文件放一起：`*.pkg.json`、设备文件、`README.md`、账本、场景、自测。
- `meta.version` 是包格式版本（当前 1）；`meta.package_version` 是包的版本。两者是不同的东西。
- 新版本 = 一个新包，装到新的版本键下；升级 = 装完后 `current` 指针改指新版本。旧版本保留，回滚就是再把指针改回去。
- 交付时说明它依赖镜像的哪些前提（例如需要 `$MEM.loader` 装载设备、需要某个 PLM 类型）。

## 讨论区

- 能力声明目前只有 README 里的文字，没有机器可读字段；是否给包加一个 `caps` 段，等第一批移植之后再定。
- 保真度目前是文字账本，没有统一评分；是否需要一份可比较的评分表，取决于移植数量。
- 自定义 PLM 不能随包分发；如果某些方案强依赖自定义执行器，要另议。
- 暂存区与"先在独立 AVM 实例里试跑"的流程还没固化，目前靠验收者手动做。
